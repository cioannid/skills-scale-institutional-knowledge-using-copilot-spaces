# OctoAcme Project Management Docs

## Overview

Welcome to OctoAcme's project management documentation. This README introduces how project management is run at OctoAcme and provides direct links to all foundational process documents.

OctoAcme's project management methodology is designed to be **iterative, customer-focused, and transparent**, ensuring that teams deliver high-quality outcomes efficiently. Our approach emphasizes:

- **Customer-first mindset**: Prioritizing customer value and usability in every decision
- **Iterative delivery**: Breaking work into small, testable increments for faster feedback
- **Clear ownership and roles**: Defining responsibilities for Project Managers, Product Managers, Developers, and QA
- **Decision gates**: Structured checkpoints at initiation, planning, execution, release, and retrospective stages
- **Transparency**: Using GitHub Projects for tracking and regular stakeholder communications
- **Data-informed decisions**: Measuring impact and iterating based on evidence
- **Continuous improvement**: Learning from retrospectives and adapting processes

## Workflow Summary

OctoAcme projects follow a structured lifecycle with five key stages:

1. **Initiation**: Validate the business need, define the problem statement, identify stakeholders, and create a project one-pager with success metrics and high-level timeline.

2. **Planning**: Turn the approved initiative into an actionable plan by creating a prioritized backlog, estimating scope, defining acceptance criteria and Definition of Done, identifying dependencies and risks, and mapping out releases and milestones.

3. **Execution & Tracking**: Build, test, review, and iterate on features using sprint/iteration cycles, daily standups, regular syncs between PM and Product Manager, and GitHub Projects for visibility and tracking.

4. **Release & Deployment**: Deploy validated features to production, verify deployment success, communicate releases to stakeholders, and ensure proper documentation and observability.

5. **Retrospective & Continuous Improvement**: Capture learnings, identify what worked well and what didn't, document action items for process improvements, and share insights across teams.

### Key Artifacts

Throughout the project lifecycle, teams create and maintain several important artifacts:

- **Project Charter / One-pager**: Problem statement, objectives, success metrics, stakeholders, and timeline
- **Roadmap and Release Plan**: High-level feature timeline and milestones
- **Sprint/Iteration Backlog**: Prioritized work items with acceptance criteria
- **Acceptance Criteria & Definition of Done**: Clear quality standards and completion requirements
- **Risk Register**: Identified risks with impact, probability, owners, and mitigation strategies
- **Retrospective Notes**: Lessons learned and continuous improvement action items

### Core Roles

OctoAcme projects involve several key roles working together:

- **Project Manager (PM)**: Coordinates delivery activities, manages schedules, risks, dependencies, and communications to ensure on-time delivery
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, measures success, and ensures the team builds the right things for customers
- **Developers**: Design, build, test, and deliver software components that meet acceptance criteria and quality standards
- **QA/Testing**: Validate quality, ensure acceptance criteria are met, and maintain high test coverage
- **Stakeholders**: Provide inputs, approvals, and business context throughout the project

### Communication Cadence

Regular communication keeps everyone aligned:

- **Weekly sync** between Project Manager and Product Manager
- **Twice-weekly standups** for the delivery team (or as agreed)
- **Monthly stakeholder updates** on progress and key decisions
- **Ad-hoc escalations** as needed for blockers or risks

## How to Use These Docs

These process documents are designed to be practical guides for project teams:

- **New team members**: Start with the [Project Management Overview](octoacme-project-management-overview.md) to understand the overall approach, then review [Roles and Personas](octoacme-roles-and-personas.md) to understand your role
- **Starting a new project**: Follow the [Project Initiation](octoacme-project-initiation.md) guide to create your one-pager and get stakeholder alignment
- **During project execution**: Reference [Execution & Tracking](octoacme-execution-and-tracking.md) for daily operations and [Risk Management & Communication](octoacme-risks-and-communication.md) for handling challenges
- **Preparing for release**: Use the [Release & Deployment](octoacme-release-and-deployment.md) checklist
- **Improving processes**: Apply insights from [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)

**Tip**: Keep your Project Charter and process-specific docs in your project repository. Add them to `.copilot/` if you want GitHub Copilot Spaces to use them as context for better assistance.
